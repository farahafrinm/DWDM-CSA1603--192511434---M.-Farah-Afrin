KNIME Workflows

The actual ETL and data-mining pipelines built in KNIME to clean the raw Excel data and prepare it for this warehouse.

Data Cleaning Pipelines

The same 5-node cleaning pattern was applied separately to each of the five raw datasets before loading them into the database.

Excel Reader → loads the raw Excel file  ·  Column Filter → keeps only the columns needed for the warehouse  ·  Duplicate Row Filter → removes duplicate records  ·  Sorter → orders rows (e.g. by HillStation_ID)  ·  Excel Writer → exports the cleaned file, ready to load into MySQL

HillStation Master

Cleans the core hill station reference data (name, state, district, elevation, coordinates) used by every other table.

Tourism Data

Cleans visitor counts, peak season, and satisfaction score records before they reach the Tourism tab and reports.

Biodiversity Data

Cleans species records (name, type, conservation status) that power the Biodiversity tab.

Damage / Threat Data

Cleans environmental damage, deforestation, pollution and overcrowding records used in the Threats tab.

Preservation Data

Cleans preservation methods, government protection status, and effectiveness score records used in the Preservation tab.

Data Integration & Mining Workflow

After cleaning, this workflow reads all five cleaned tables back in and joins them together on HillStation_ID using a chain of Joiner nodes, producing one combined, analysis-ready table (viewed live with the Table View node). This combined table is what the star schema's fact table and the OLAP cube's cross-category analysis are built from.

Combined Table Build

Five Excel Reader + Column Filter branches (one per cleaned dataset) feed into a chain of Joiner nodes, merging every category — station, tourism, biodiversity, damage, and preservation — into a single wide table for cross-category analysis.
